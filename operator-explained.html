Stream Computing · Field Notes 01

算子 — 流计算的原子单元

把无界数据流当作一条河,算子(Operator)就是河上一个个独立的水车。每个水车只做一件事:接进来,变一下,送出去。一条作业,本质上就是几十个水车按特定拓扑串成的有向图。

DEFINITION有状态/无状态计算单元 TOPOLOGY有向无环图 DAG EXEC并行 × 流水线 × 链化
01

什么是算子

DEFINITION

算子是流处理框架(Flink / Spark Streaming / Storm)里最小的、可被独立调度和并行化的计算单元。它接收一个或多个输入流,执行确定的转换,产生一个或多个输出流。

FORMALLY · 形式化

一个函数 + 一份状态

算子 = 用户函数 (UDF) + 可选的本地状态。函数定义"如何变",状态保留"上次的事"。无状态算子如 map,有状态如 reduce。

PRACTICALLY · 实际形态

一个并行的工作单元

每个算子有 parallelism,实例化为多个 SubTask 分布在 TaskManager 上。同 key 的数据被路由到同一实例,保证状态本地性。

KEY INSIGHT · 设计哲学

纯粹、组合、可放缩

每个算子只做一件事,通过组合表达复杂逻辑;每个都可独立并行,通过水平扩展应对压力。这是流式系统能伸缩的根。

02

算子分类

TAXONOMY · 04

按职责可粗分为四类。任何流式作业,都是它们的排列组合。

SOURCE · 入口

数据从哪里来

从 Kafka、Pulsar、文件、Socket、CDC 等接入数据,产生第一份事件流。负责水位生成、断点续传、并行读取分片。

TRANSFORM · 转换

数据如何变换

主体逻辑层。map / filter / flatMap / keyBy / window / reduce / process 等等。

CONNECT · 合流

多个流如何汇

处理多输入:union 同类合并、connect 异类配对、coGroup 共组、broadcast 广播规则。

SINK · 出口

数据到哪里去

写出到 Kafka、ES、ClickHouse、HDFS、JDBC。负责事务提交、两阶段协议、Exactly-Once 语义保证。

04

关键属性

PROPERTIES · 06

理解一个算子,主要看这六个维度。运维与调优,几乎都在这六根弦上拨。

PARALLELISM
并行度 — 算子实例化为多少个 SubTask。可独立设置,瓶颈算子可单独提高,而不必抬整作业。
STATEFULNESS
是否有状态 — 无状态算子(map / filter)易并行;有状态(reduce / window / join)需配合 keyBy 与状态后端(Heap / RocksDB)。
KEYED / NON-KEYED
是否分键 — KeyBy 之后的算子状态按 key 隔离,可水平扩展;否则只能维护 operator-level 状态,扩展受限于实例数。
CHAINING
算子链 — 同并行度且 forward 关系的相邻算子会被合并成一个 Task,函数调用代替网络传输,延迟下降一个数量级。
WATERMARK
水位线 — 算子内部维护水位,驱动 EventTime 窗口触发。多输入算子取最小水位,确保正确性。
CHECKPOINT
检查点 — 算子状态快照随 barrier 写入 DFS,失败时从 barrier 处恢复,实现 Exactly-Once 语义。
05

算子链 — 性能的隐形开关

CHAINING

框架会把满足条件的相邻算子合并成一个执行单元,函数级调用代替进程间序列化。这是 Flink 默认开启的最大单点优化,也是新人最容易忽略的细节。

CONDITION · 触发条件

三个全部满足

① 上下游并行度相同 ② 数据交换是 forward(无 shuffle)③ 没有显式 disableChaining。少一条都不行。

EFFECT · 收益

调用代替网络

原本 N 个算子 → N 个 Task,数据要序列化-反序列化 N-1 次;链化后 1 个 Task,纯函数调用,延迟下降 5–10x。

TRADE-OFF · 取舍

什么时候要拆开

某算子 CPU 重(如调用模型推理),会拖慢整链。此时主动 startNewChain() 把它独立出去,让前后算子继续串。
